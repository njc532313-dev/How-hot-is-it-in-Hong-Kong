# Pastel Journey UI Design Guide

> 這份規範由參考圖的視覺語言提煉而成，用於建立同風格的旅遊、生活方式或探索型行動介面。它不是逐像素臨摹稿，而是一套可延展、可落地的設計系統。

## 1. 風格定位

### 一句話定義

以奶油白介面為基底，結合低飽和自然色、童趣扁平插畫、大圓角卡片與柔和陰影，營造溫暖、輕鬆、帶故事感的旅遊探索體驗。

### 關鍵詞

- 溫暖、友善、療癒
- Pastel / Soft UI / Flat Illustration
- 大圓角、低對比、低銳度
- 旅遊明信片感
- 輕量、休閒、非商務
- 圖像主導、資訊適量

### 適用場景

- 旅遊探索與景點預訂
- 城市指南、活動推薦
- 生活方式與休閒內容 App
- 親子、戶外或度假產品

### 不適合直接套用

- 高密度資料後台
- 金融交易、醫療監控等高警示場景
- 需要冷峻、專業或極高資訊密度的產品

## 2. 核心設計原則

### 2.1 插畫先說故事，文字負責決策

大面積插畫負責營造目的地氣氛，文字只保留名稱、地點、距離、時段與價格等決策資訊。避免在插畫卡片上疊放長段說明。

### 2.2 柔和不等於模糊

背景與裝飾可使用低飽和色，但標題、價格、主要按鈕與互動狀態必須保持清晰。主要正文與背景的對比度至少達到 4.5:1。

### 2.3 用色塊建立層級，不依賴邊框

主要層級由背景色、卡片色、插畫色與留白建立。邊框只用於焦點、選取或必要分隔，不為每個元件加線框。

### 2.4 圓角要有層級

頁面容器、內容卡片、圖示底座和按鈕都可使用圓角，但尺寸越大，圓角越大；避免所有元件統一使用同一個半徑。

### 2.5 一個畫面只保留一個最強行動

橙色用於搜尋、預訂或當前選取等首要操作。次要功能保持白色、灰色或淡綠色，避免每個按鈕都搶注意力。

## 3. 色彩系統

以下色值是根據參考圖整理的建議起點；正式產品應在真機上檢查螢幕差異與對比度。

### 3.1 核心色票

| Token | 色值 | 用途 |
|---|---:|---|
| `color.canvas` | `#DCE7AF` | 品牌展示背景、空狀態背景；不作長文底色 |
| `color.surface` | `#FFFDF8` | App 主背景、主要卡片 |
| `color.surfaceSoft` | `#F8F3EC` | 搜尋區、次層容器、底部導覽背景 |
| `color.primary` | `#FF824A` | 主要 CTA、搜尋按鈕、選取狀態 |
| `color.primaryHover` | `#F26F38` | Hover 或強調態 |
| `color.primaryPressed` | `#DD5E2E` | Pressed 狀態 |
| `color.peach` | `#FFC2A5` | 插畫天空、暖色卡片背景 |
| `color.apricot` | `#FFB34F` | 插畫高光、標記與輔助圖形 |
| `color.sage` | `#BFD47A` | 優惠資訊、自然主題輔助色 |
| `color.forest` | `#4F806A` | 插畫山丘、植物深色層 |
| `color.sky` | `#8EC8F2` | 冬季、天空或冷色目的地卡片 |
| `color.ink` | `#242221` | 標題、主要文字 |
| `color.textSecondary` | `#69635F` | 地點、說明文字 |
| `color.textMuted` | `#938A85` | 非關鍵標籤、未選取導覽 |
| `color.line` | `#ECE5DE` | 必要分隔線 |
| `color.focus` | `#2F6FED` | 鍵盤焦點外框，不與品牌橙混淆 |

### 3.2 色彩比例

- 60% 奶油白與暖灰表面
- 20% 插畫中的蜜桃、杏橙與自然綠
- 10% 品牌橙與 CTA
- 10% 天空藍、深綠等情境輔助色

### 3.3 用色限制

- 同一畫面最多保留 1 個高飽和主色與 2 個低飽和輔助色。
- 大面積背景不用純白 `#FFFFFF`，優先使用偏暖的 `#FFFDF8`。
- 不用淡橙文字直接承載重要資訊；橙色若作文字，需確認對比度。
- 圖表不能只靠顏色表達選取狀態；同時使用紋理、描邊或文字標籤。

## 4. 字體與排版

### 4.1 字體建議

- 英文與數字：`Poppins`
- 繁體中文：`Noto Sans TC`
- 系統後備：`-apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`

選擇圓潤、幾何感較強的無襯線字體。避免使用過細字重，柔焦背景會降低細字的辨識度。

### 4.2 字級階層

| 樣式 | 手機尺寸 / 行高 | 字重 | 用途 |
|---|---|---:|---|
| Display | `32 / 40` | 600 | 首頁問候、少量品牌標題 |
| H1 | `28 / 36` | 600 | 景點名稱、頁面主標題 |
| H2 | `22 / 30` | 600 | 區段標題 |
| H3 | `18 / 26` | 600 | 卡片標題、優惠標題 |
| Body | `16 / 24` | 400 | 一般內容 |
| Body Small | `14 / 21` | 400 | 地點、距離、輔助資訊 |
| Label | `12 / 16` | 500 | 導覽與圖表刻度；不再更小 |
| Button | `17 / 24` | 600 | 主要按鈕 |

### 4.3 排版規則

- 標題使用 sentence case，不使用全大寫。
- 介面文字以左對齊為主；主要 CTA 可置中。
- 標題與副標題間距 `4–8px`，區段標題與內容間距 `16–20px`。
- 卡片標題最多兩行，目的地名稱優先保持單行並以省略號截斷。
- 價格與距離等數字可提高一級字重，但不要同時放大、加粗又換色。

---

## 5. 版面與間距

### 5.1 基準

- 以 `4px` 為最小單位，主要使用 `8px` 網格。
- 手機頁面水平邊距：`20–24px`。
- 小型元件內距：`12–16px`。
- 一般卡片內距：`20–24px`。
- 區段間距：`28–32px`。
- 主要段落間距：`40–48px`。

### 5.2 建議 spacing tokens

```text
space.1 = 4px
space.2 = 8px
space.3 = 12px
space.4 = 16px
space.5 = 20px
space.6 = 24px
space.8 = 32px
space.10 = 40px
space.12 = 48px
```

### 5.3 安全區與固定元件

- 頂部內容需避開狀態列與瀏海安全區。
- 固定底部 CTA 與導覽列需包含裝置底部安全區。
- 可捲動內容底端需增加與固定 CTA 等高的 inset，避免最後一項被遮住。
- 375px 寬的小型手機上，目的地卡片仍應完整露出主標題和主要插畫焦點。

---

## 6. 圓角、陰影與層級

### 6.1 圓角 tokens

| Token | 數值 | 用途 |
|---|---:|---|
| `radius.sm` | `12px` | 小縮圖、標籤 |
| `radius.md` | `18px` | 圖示底座、優惠條 |
| `radius.lg` | `24px` | 搜尋框、標準卡片 |
| `radius.xl` | `32px` | 大型目的地卡、底部詳情面板 |
| `radius.pill` | `999px` | CTA、距離膠囊、圓形按鈕 |

圓角不可大於元件短邊的一半；圖片、遮罩與卡片應共用相同外輪廓，避免角落露底。

### 6.2 陰影 tokens

```text
shadow.soft   = 0 8px 24px rgba(90, 72, 58, 0.08)
shadow.float  = 0 14px 36px rgba(90, 72, 58, 0.12)
shadow.button = 0 6px 16px rgba(255, 130, 74, 0.24)
```

- 陰影偏暖灰，不使用純黑重陰影。
- 同一畫面最多兩個 elevation 層級。
- 不同層級靠陰影範圍與表面色區分，不靠模糊光暈。

---

## 7. 元件規範

### 7.1 搜尋框

- 高度：`56–64px`
- 圓角：`24–32px`
- 背景：`surface`
- 左側為明確提示文字；右側圓形搜尋按鈕使用品牌橙。
- 搜尋按鈕視覺尺寸可為 `44px`，實際點擊區至少 `48 × 48dp`。
- Focus 時加 `2px` 藍色焦點環，不只改變陰影。
- Placeholder 不可取代欄位標籤；若進入完整搜尋流程，需顯示持續可見的 label。

### 7.2 快捷入口

- 每列最多 4 個。
- 圖示底座約 `56–64px`，圖示 `22–24px`。
- 同一層級統一使用 outline 或 filled 圖示，不混用 emoji。
- 圖示下方標籤以 `12–14px` 顯示，最多兩行。
- 點擊區至少 `48 × 48dp`，入口之間保持至少 `8px` 間隔。

### 7.3 目的地卡片

- 建議比例：直式約 `4:5` 至 `3:4`。
- 卡片以插畫為主，文字置於左上安全區。
- 標題與地點使用深色，不加投影；必要時在文字後加入淡色局部遮罩。
- 首張卡片可完整展示，下一張露出約 `12–20%`，暗示水平滑動。
- 若支援滑動，也必須提供分頁指示或可點擊控制，不依賴手勢作為唯一操作。

### 7.4 詳情頁 Hero

- 插畫佔首屏上方約 `34–42%`。
- 返回按鈕置於安全區內，使用白色圓形底座，點擊區至少 `48 × 48dp`。
- 下方詳情面板以大圓角向上覆蓋 Hero 約 `20–32px`，形成柔和的前後景關係。
- 地點、距離等次要資訊應靠近主標題，但視覺權重至少低一級。

### 7.5 優惠橫幅

- 使用淡鼠尾草綠背景與深色文字。
- 左側圖示、中間資訊、右側箭頭，保持單一閱讀方向。
- 高度約 `72–88px`；整條可點擊時，需提供完整 pressed 狀態。
- 折扣百分比與有效期限應使用文字說明，不只顯示圖示。

### 7.6 柱狀圖／人流預測

- 柱體採圓角矩形，基礎色為淡蜜桃。
- 當前或推薦時段使用品牌橙，並增加斜紋或標籤，避免只靠顏色區分。
- 僅顯示關鍵時間刻度，避免每根柱都加文字。
- 若可互動，點按後顯示具體數值、時段與「較少／一般／繁忙」描述。
- 圖表需提供螢幕閱讀器可讀的等價摘要。

### 7.7 主要 CTA

- 高度：`56–64px`
- 圓角：`20–28px` 或 pill
- 背景：`primary`
- 文字預設使用深色 `color.ink`；參考圖中的白字配亮橙通常不足 `4.5:1`，若堅持白字，需把按鈕底色加深至實測合格。價格可用較高字重。
- 文案使用「動詞＋結果」，例如「立即預訂 · $120」。
- Pressed 狀態用較深底色或降低 elevation，不縮放導致版面跳動。
- Loading 時保留按鈕寬度，顯示進度並阻止重複送出。

### 7.8 底部導覽

- 最多 5 個入口，建議 4 個。
- 選取狀態同時使用顏色與形狀／指示線。
- 圖示大小 `22–24px`，觸控區至少 `48 × 48dp`。
- 不選中項使用暖灰，而不是極淡灰。
- 導覽列須避開系統手勢區。

## 8. 插畫系統

### 8.1 造型語言

- 幾何化、扁平化，以圓、拱形、梯形與柔和曲線構成。
- 風景分成前景、中景、背景 3–5 層，以色塊深淺製造空間感。
- 主體輪廓簡潔、局部略帶不對稱，避免過度精準的工程感。
- 人物與建築可省略細節，但地標輪廓必須容易辨識。

### 8.2 色彩與材質

- 不使用寫實漸層、金屬、高光玻璃或高噪點材質。
- 可使用非常輕微的紙張顆粒，透明度控制在 `2–4%`。
- 每張插畫保留一個暖色焦點與一個深色錨點。
- 相鄰卡片可切換季節色，但線條粗細、形狀語言與飽和度需一致。

### 8.3 構圖規則

- 文字安全區約佔卡片上方 `20–28%`。
- 主地標靠中間或略偏右，避免與標題重疊。
- 視覺重心偏下，讓天空形成呼吸空間。
- 小縮圖應使用原插畫的重新裁切版本，不直接把完整大圖等比縮小到看不清。

## 9. 動效與回饋

### 9.1 時間 tokens

```text
motion.fast   = 120ms
motion.base   = 220ms
motion.slow   = 360ms
ease.standard = cubic-bezier(0.2, 0.8, 0.2, 1)
ease.exit     = cubic-bezier(0.4, 0, 1, 1)
```

### 9.2 建議動效

- 點按回饋：`80–150ms` 內出現顏色、透明度或 elevation 變化。
- 卡片進場：淡入並向上位移 `8–12px`，不使用大幅彈跳。
- 詳情轉場：卡片插畫可平滑延續為 Hero，內容面板再淡入。
- 水平卡片滑動：吸附至卡片邊界，保留下一張預覽。
- 圖表選取：柱體顏色與紋理在 `180–240ms` 內切換。

### 9.3 限制

- 不做持續漂浮、閃爍或無目的循環動畫。
- 避免動畫 `width`、`height` 導致重排，優先使用 `transform` 和 `opacity`。
- 開啟 `prefers-reduced-motion` 時取消位移、視差與交錯進場，直接呈現最終狀態。

## 10. 無障礙與可用性底線

- 正文與背景對比度至少 `4.5:1`；大型文字至少 `3:1`。
- 有意義的圖示與控制項相對背景至少 `3:1`。
- iOS 點擊區至少 `44 × 44pt`；Android 至少 `48 × 48dp`。
- 所有 icon-only button 都需要可讀名稱，例如「返回」「搜尋」「開啟聊天」。
- 裝飾插畫從 accessibility tree 隱藏；若插畫傳達目的地資訊，提供簡短替代文字。
- 焦點順序與視覺順序一致，固定底部 CTA 不可遮住鍵盤焦點。
- 支援 Dynamic Type／較大字體；放大時允許標題換行，不固定卡片文字高度。
- 不能只用顏色表示目前分頁、選取時段或導覽狀態。
- 所有滑動操作都需有按鈕或點按替代方案。

## 11. 響應式策略

### 小型手機（320–374px）

- 水平邊距降至 `16px`。
- 快捷入口保持 4 欄，但文字最多兩行；若仍擁擠則改為 2 × 2。
- CTA 文字縮短，不縮小至 16px 以下。
- 詳情頁距離膠囊可移至地點文字下方。

### 一般手機（375–479px）

- 採用本規範的基準尺寸。
- 目的地輪播顯示 1 張完整卡片與下一張局部預覽。

### 平板與橫向模式（≥768px）

- 不把手機內容無限拉寬；主內容最大寬度建議 `720–840px`。
- 可改為左側插畫、右側詳情的雙欄版式。
- 卡片網格改為 2–3 欄，但維持相同插畫比例與文字安全區。
- 橫向模式必須重新檢查固定 CTA、底部安全區與可視內容高度。

## 13. Do / Don't

### Do

- 使用大面積留白與一個明確視覺焦點。
- 讓插畫與功能色共享同一套低飽和色盤。
- 用卡片露出下一項，暗示內容可探索。
- 用橙色集中引導主要行動。
- 保持圖示家族、描邊粗細和圓角邏輯一致。
- 在真機上測試小尺寸、橫向、較大字體與 reduced motion。

### Don't

- 不混用寫實照片、3D icon、emoji 與扁平插畫。
- 不為每個區塊增加陰影、邊框或漸層。
- 不使用極淡灰承載必要資訊。
- 不用多個高飽和按鈕競爭注意力。
- 不把所有卡片做成同一尺寸與同一圓角。
- 不讓固定底部操作遮住最後一段內容。
- 不以滑動、hover 或顏色作為唯一互動提示。

---

## 14. 驗收清單

- [ ] 畫面第一眼能辨認唯一的主行動。
- [ ] 插畫、圖示與 UI 使用一致色盤與造型語言。
- [ ] 頁面水平間距、卡片內距與區段間距遵循 4/8px 網格。
- [ ] 圓角有清楚層級，圖片遮罩沒有露底。
